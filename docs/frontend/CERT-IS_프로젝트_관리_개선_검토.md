# CERT-IS 프로젝트 관리 관점 개선 검토

검토일: 2026-10-06

현재 와이어프레임 전체 소스, 실제 화면, 상세 설계 기록과 WBS를 대조한 검토임. 이번 작업은 개선 사항 기록이며 기능 수정 작업은 아님. 로그인·API·DB·WebSocket·Gemini는 아직 연결되지 않았으므로 그 영역은 미구현 또는 설계 과제로 표시함. 실제 서버의 완료 상태나 오류를 추정하지 않음.

최근 사용자 피드백인 사이드바 유지, 독립 채팅 공간, 독립 스크롤, 베이지 색상, UI 축소, 사이드바 홈 통합, 임원진 전체 활동 조회를 현재 기준으로 적용함. 이전 상세 설계 기록과 다른 부분은 최신 피드백을 우선함.

**우선순위**

- P0: 데이터 신뢰성을 해치는 동작 수정 또는 FE·BE 구조를 정하기 전 합의할 항목임.
- P1: 실제 사용 가능한 최소 구현에 포함하거나, 명시적으로 범위에서 제외해야 할 항목임.
- P2: 기본 흐름을 완성한 뒤 필요에 따라 추가할 항목임.

**분류**

- 현재 문제: 소스 또는 화면에서 실제로 확인한 동작 불일치임.
- 미구현: 계획 기능 또는 운영에 필요한 흐름이 현 시제품에 아직 없음.
- 정책 미정: 팀에서 결정해야 하는 항목임. 추천을 확정 정책으로 취급하면 안 됨.
- 개선 제안: 현재 요구를 더 잘 수행하기 위한 선택임.

**유지할 방향**

사이드바의 홈 하나, 고정 채팅 공간, 독립 스크롤, 팀 캘린더 기본 진입, 공통 예약 기능, 채팅과 연결된 Markdown 문서 구조는 유지할 가치가 있음. 불필요한 카드·메뉴를 다시 늘리기보다 현재 작업 공간에서 필요한 정보와 행동만 제공하는 방향이 적절함.

## 14. 실제 확인 근거와 검증 범위

- 활동 생성 폼을 열어 이름·유형·보안 분야·한 줄 설명만 있는 것을 확인했음.
- 웹 취약점 연구의 방 생성 폼에서 혜림이 참여자 후보로 표시되는 것을 확인했음. 소스의 해당 활동 구성원에는 혜림이 없음.
- 메인 CERT-IS 통합 관리와 채팅 웹 취약점 연구를 동시에 선택할 수 있는 것을 확인했음. 전체 render의 자동 동기화는 소스에서 확인했음.
- 임원진의 개인 캘린더에서 미참여 활동의 침해 로그 분석 일정이 표시되는 것을 확인했음.
- 임원진의 미참여 활동 문서에서 저장은 비활성인데 편집·미리보기 및 저장 안내가 남는 것을 확인했음.
- 같은 프로젝트의 기태 예약이 다른 팀 예약으로 표시되는 것을 확인했음.
- 네트워크 관심·경험 있음으로 응답해도 웹 보안 예시가 나오는 것을 확인했음. 이는 명시된 시제품 동작임.
- D01은 Node의 격리된 실행 환경에서 실제 앱 이벤트 처리 함수를 실행해 검증했음. 문서 보기 전환만으로는 저장 공간이 바뀌지 않지만 이후 메시지 전송에서 저장 버튼 없이 초안이 저장되는 것을 재현했음. 사용자 브라우저의 문서·대화 데이터는 이 검증에서 변경하지 않았음.
- S04는 초기 fixture의 documents[8], documents[9]가 없는 것을 확인했음. 제품 데이터 유실을 재현한 것으로 해석하면 안 됨.
- 브라우저 검토 중 오류 로그는 확인되지 않았음. 오류가 없다는 것과 운영 기능이 완성됐다는 것은 다름.
- 이번 검토는 제품 설계·프론트 시제품 기준임. 서버 동시성·보안·배포·복구 검증은 수행하지 않았음.
